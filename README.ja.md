# Codex Usage Tray

[English](README.md) · [Windows・Mac版ダウンロード](https://github.com/zeusu-sato/codex-usage-tray/releases/tag/v0.4.0) · [プライバシー](docs/PRIVACY.md)

CodexとClaude CodeのUsage残量を、Windowsの通知領域・Macのメニューバーに表示する非公式アプリです。数字とゲージで残量を確認でき、マウスを重ねると残量とリセット時刻を表示します。同じウィンドウから、各利用枠の詳細、Codexのバージョン、任意の追加対策を確認できます。

**v0.4.0はWindows x64・macOS 13以降（Apple Silicon／Intel）向けの初期ベータ版です。UIは日本語です。** OpenAI・Anthropicとは独立した非公式プロジェクトです。

![Demo：テスト用の残量を表示した、追加対策未設定のアプリ画面](docs/images/demo.png)

実際のアカウント情報を使わないデモ画像です。[capture-dual-demo.ps1](windows/capture-dual-demo.ps1)でネイティブUIから撮影しています。

## Codex + Claude

**v0.3.0でClaude Codeの試験対応を追加しました。** 2つのトレイアイコンと共通画面から、両方の残量を確認できます。

- 通知領域に2個のアイコンを表示し、共通ウィンドウのCodex・Claudeタブを開きます。アイコンのクリックで対応するタブへ移動します。監視対象・残量履歴・見直し記録・追加対策スイッチは製品ごとに分離します。
- シンボルは、インストール済みの公式VS Code / Insiders拡張機能から読み取り、数字の背後に**不透明度18%**で描画します。画像は同梱しません。利用できる画像がなければ数字とゲージのみ表示します。
- Claudeの残量取得は実験的な対応で、**Claude Code 2.1.263だけ**を対象にします。インストール済みCLIの内部`initialize` / `get_usage`制御を使い、追加動作を無効にして、プロンプトを送りません。他のバージョンではメタデータ取得用の起動前に停止し、未対応の応答も未確認扱いにします。安定した公開APIへの対応を保証するものではありません。
- Claudeの数字は**全体の5時間枠・週間枠のみ**で、両方の取得が必要です。モデル別制限・追加利用分は含まず、すべてのモデルの利用可否を示すものではありません。リセット時刻がnullでも既知の残量は表示しますが、その枠の予測は行いません。
- アカウントの連続性は、ローカルのランダムsaltを使ったHMAC-SHA256で区別します。メール・組織名・アカウント名の原文は保存せず、salt・仮名化した識別値・上限付き残量履歴だけを製品別キャッシュに保存します。識別できない場合は予測せず、アカウントが変われば履歴を区切ります。[プライバシー](docs/PRIVACY.md)もご覧ください。
- 通常の残量・バージョン確認と概算では**AI推論を使いません**。Claudeの**AI見直しにもCodexを使用**し、**はい**を選んだ場合だけCodexのUsageを消費します。下記と同じ最上位モデル・最大推論強度の選択手順に従い、選択が曖昧なら推論前に確認します。

Claudeの監視には既存のClaude Codeとログインが必要で、AI見直しにはCodexも必要です。Claudeの候補を別途ONにすると、`%USERPROFILE%\.claude`（または`CLAUDE_CONFIG_DIR`）のグローバル`CLAUDE.md`へ条件付きブロックを追加します。Codexの適用先は引き続き`AGENTS.md`です。クライアント本体・認証情報は同梱しません。

## 使い始める

1. 使用するCodex・Claude Codeを別途インストールし、それぞれでログインしてください。VS Code / VS Code Insidersの拡張機能、または`PATH`上のネイティブ実行ファイルを検出します。Claudeの残量取得は現在**2.1.263**が対象です。未導入の側は、そのタブで未確認表示になります。
2. [Releases](https://github.com/zeusu-sato/codex-usage-tray/releases/tag/v0.4.0)からWindows x64版ZIPをダウンロードし、**フォルダー全体を展開**して`CodexUsageTray.exe`を起動します。隣の`backend`フォルダーも必要です。Python実行環境を同梱しているため、PythonやAnacondaのインストールは不要です。Codex・Claude Code本体は同梱していません。
3. 同じ製品の対応クライアントが複数ある場合は、監視対象を選びます。後から各トレイアイコンのメニューで変更できます。CodexとClaudeの選択は独立しています。
4. 常に残量を表示するには、Windowsの **^** 内からアイコンを通知領域へドラッグしてください。表示位置はWindows側の設定です。[Microsoft公式の説明](https://support.microsoft.com/en-us/windows/experience/personalization/customize-the-taskbar-in-windows)でもこの操作を案内しています。

ウィンドウを閉じると通知領域に残ります。各アイコンのクリックで対応するタブを開き、メニューの **終了** で常駐を終了します。同じデータ保存先でアプリを再起動すると、既存のウィンドウを開きます。Windowsログイン時の起動は初期状態では無効です。必要ならメニューの **Windowsログイン時に起動** を有効にしてください。`CodexUsageTray.exe --tray`でウィンドウを隠した状態から起動できます。

## 残量表示の読み方

起動時と、常駐中の **5分ごと** に残量を取得します。**更新** または **今すぐ確認** でも取得できますが、短時間に連続した操作は間隔を制限します。インストール済みCodexのapp-serverに対し、公式の`account/rateLimits/read`で利用制限のメタデータを取得します。この定期確認ではAIの会話や推論ターンを開始しません。[公式app-serverドキュメント](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt)

大きな数字は、各製品で対象とする枠のうち最も少ない残量です。Codexは**Codex用の利用枠**、Claudeは上記の全体5時間枠・週間枠を使います。ウィンドウには各枠のリセット時刻も表示します。別モデル用の枠や予備枠を混ぜて計算しません。

| 表示 | 意味 |
| --- | --- |
| 緑の数字 | 最近の消費ペースなら、リセットまで余裕がありそうです。 |
| 黄の数字 | リセットまでの余裕が小さい、または残量の丸め誤差を考慮すると見通しが不確かです。 |
| 赤の数字 | このペースではリセット前に不足しそう、または残量が0です。 |
| 灰色の数字 | 残量は取得できていますが、傾向の判定待ち、または予測できない状態です。 |
| `0` | 取得した利用枠の残量が0です。 |
| 灰色の`?` | 現在値が未確認、古い記録、またはサーバーの制限通知により利用可否を判断できない状態です。 |

前回取得した値を詳細欄に残す場合は、過去の記録であることを明示します。リセット予定時刻を過ぎただけで100%になったとは扱いません。サーバー側の反映時間と5分の取得間隔による遅れがあります。トークン消費量の計測や、残り何件作業できるかの予測ではありません。この版の日付・時刻表示は **日本標準時（JST / UTC+9）** です。

色は **最近の消費ペースでリセットまで持つか** の目安で、数字は常に取得した実残量です。残り90%でも減り方が速ければ赤、残り10%でもリセット直前で余裕があれば緑になります。**見通し** 欄に対象の利用枠と理由を表示します。

既存の5分ごとの取得結果だけを使い、直近24時間までの平均消費ペースから概算します。保存するのは各枠につき最大289件の時刻と残量で、既存の残量キャッシュ内に収まります。報告値の精度として消費量と残量の両方に1ポイントの幅を考慮します。消費量を多め・残量を少なめに見積もっても、その残量の20%以上が残る場合に緑、消費量を少なめ・残量を多めに見積もっても不足する場合に赤、その間は黄です。複数の枠がある場合は最も注意が必要な見通しを色に反映し、すべての枠に余裕があるときだけ緑にします。

判定には3回以上の記録と、Weeklyなら約1時間、5時間枠なら約30分（最短15分）の履歴が必要です。最初は灰色の数字と **判定待ち** を表示します。リセット、残量の増加、時計の巻き戻り、監視対象の変更時には履歴を区切ります。リセット時刻が不明なときや古い記録では、余裕ありと判断しません。休止時間を含む大まかな平均なので、使い方が変われば見通しも変わります。**AI・取得頻度・通信・常時分析用プロセスは増やしません。**

## バージョン監視と任意のAI見直し

**15分ごと** に、各製品で選択したクライアントのローカル情報と保存した基準を比較します。この確認ではAIもWeb検索も使いません。最初に記録した基準は **監視開始時** と表示します。初回のバージョン記録だけで、対策を検証済みと判断したり、追加対策が必要と判断したりはしません。

対象クライアントの変更を検知すると通知し、**AIで対策を見直しますか** と確認します。変更がなくても **AIで見直す…** から手動で依頼できます。

- **はい** を選んだときだけ、画面に見えるCodexのコンソールを開いてAI見直しを開始します。この処理はCodexのUsageを使用します。見直し用フォルダーを範囲とする`workspace-write`サンドボックスを使い、既存の承認設定を引き継ぎます。
- **いいえ**、Escape、確認画面の×ではAIを開始しません。同じ変更に対する辞退を保存します。後から手動で再度依頼できます。
- 推論前に、その時点の`model/list`を取得し、利用可能な最上位モデルと対応する最大推論強度を選びます。速度は **Standard** です。利用可能なモデルと推論強度は公式APIで取得します。[モデル一覧の公式説明](https://learn.chatgpt.com/docs/app-server#list-models-modellist)
- APIにモデル品質の順位を示す共通フィールドはありません。公式カタログの説明から最上位を一意に判断できる場合だけ自動選択します。説明が曖昧、または推論強度の順序が未知の場合は、**推論を始める前にコンソールで選択を求めます**。名前順やデフォルト指定を品質順位とみなさず、弱いモデルへの無断切り替えもしません。

見直しでは報告書を作り、必要に応じて追加指示を提案します。**見直し結果を開く** から内容を読めます。完了した結果について、報告書・根拠の記録・所定の形式・対象環境の一致をアプリが確認できた場合に限り、基準を「見直し済み」とします。Codexの起動や終了だけでは更新しません。この整合性確認は、AIの結論の正しさを独立して証明するものではありません。報告内容はユーザーによる確認が必要です。

## 追加対策は初期状態では未設定

公開版には特定の追加対策を入れていません。初回は **Codexの通常動作** を使用します。見直しの結論が「追加対策は不要」になる場合もあります。スイッチは、現在の環境に適用できる候補があるときに使えます。

報告書を読んで **追加対策** を **ON** にすると、グローバルなCodexの`AGENTS.md`（通常は`%USERPROFILE%\.codex\AGENTS.md`、`CODEX_HOME`設定時はその場所）へ、アプリ管理の条件付き指示ブロックを追加します。これはプロジェクトをまたいで使われるCodexの指示です。既存のユーザー記述を保持し、変更前の内容をローカルにバックアップします。条件部分には、ユーザーのモデル・推論強度・必要な品質確認を維持する指示が含まれます。

**OFF** にすると対策を停止し、アプリが追加した未変更のブロックだけを取り除きます。そのブロックをユーザーが編集していた場合は、自動上書きせず保護します。Codexの変更・確認失敗、スイッチの無効化、確認用アプリの欠落・実行失敗時は、既存の会話に残ったコピーも含め、旧対策を適用しない条件になっています。固定の日付による期限はなく、更新後に自動で再有効化もしません。

このアプリは **Usage削減を一般的に保証するものではありません**。特定のサブエージェント動作が過剰なUsageの原因だと断定するものでもありません。提案する指示は、調べた根拠と環境に応じたものです。

スイッチはONでつまみが右、OFFで左になります。確認中・未確認は別表示にし、切り替えが成功してから表示を更新します。

## 保存データ・困ったとき・削除

保存先は`%LOCALAPPDATA%\CodexUsageTray`です。最小限の残量記録、対象Codexと監視基準、通知への回答、見直し結果、対策状態を保存します。AGENTSのバックアップには個人の指示内容が含まれる場合があります。これらを配布ZIPに含めません。アプリは認証情報を読み取り・コピーせず、ログインはインストール済みCodexが扱います。アプリ独自のアクセス解析はありません。Codex自身の通信・ログ・データ設定は引き続き適用されます。[プライバシーの詳細](docs/PRIVACY.md)

`?`が表示されたら、選択したCodexとそのログイン状態を確認し、**今すぐ確認** を実行してウィンドウの説明を読んでください。未対応のアカウントや応答形式、Codexの未検出、接続不能などで未確認になる場合があります。このアプリからログインしたり、トークンを貼り付けたりする必要はありません。

削除するときは、先に有効な追加対策とログイン時起動を無効にし、**終了** を選んでから展開フォルダーを削除します。`%LOCALAPPDATA%\CodexUsageTray`は別に残るため、報告書やバックアップが不要な場合だけ削除してください。移動する場合も、実行ファイルへの参照を持つ追加対策とログイン時起動を先に無効にしてください。アプリの更新は手動です。自己更新や定期的なオンライン調査は行いません。

## ソースコードと開発

このバージョン確認が検知するのは、インストール済みCodexの変更です。クライアント更新を伴わないサーバー側のモデル・課金・挙動の変更は検知できません。気になる変化があれば手動で見直しを依頼できます。

[GitHubでソースコードを公開](https://github.com/zeusu-sato/codex-usage-tray)しています。アプリのコードは[MITライセンス](LICENSE)です。UIはWindows Forms / .NET Framework、バックエンドはPythonをPyInstallerのone-directory形式で同梱します。同梱する依存物にはそれぞれのライセンスが適用されます。

Windows上のソース取得先で、UIのビルドと分離したUIテストを実行できます。

```powershell
.\windows\build.ps1
powershell.exe -NoProfile -STA -File .\windows\test-ui.ps1
powershell.exe -NoProfile -STA -File .\windows\test-dual-ui.ps1
```

この手順はUIをビルドし、テスト用バックエンドで検証します。製品用バックエンドのパッケージ作成や実際のAI呼び出しは行いません。v0.4.0の範囲と制約は[リリースノート](docs/RELEASE_NOTES.md)をご覧ください。公開Issueには、残量記録、認証情報、個人の指示、未編集の見直しファイルを添付しないでください。

配布ZIP全体を作る場合は、Windows x64、CPython 3.13.15、.NET Frameworkのコンパイラーを使用します。

```powershell
python -m venv .venv
.\packaging\build.ps1 -Python .\.venv\Scripts\python.exe
```

固定したビルド用依存物をインストールし、バックエンドのテスト後に`dist/CodexUsageTray-0.4.0-windows-x64.zip`と`SHA256SUMS.txt`を作成します。WindowsのワークフローではUIテストも実行します。AI起動はテスト用の代替処理で確認し、認証情報や実際のAI呼び出しは使いません。将来のAIの調査結果が正しいことを保証するテストではありません。
