# Mac実機での確認（v0.4.1）

対象はmacOS 13以降です。この手順書は現行版に合わせて更新します。WindowsのClaude 2.1.266では残量取得を確認済みですが、**Mac実アカウントでの残量取得、Keychain、初回の起動許可、ログイン時起動、実際のAIレビューは未確認です。** 両CPUの架空データによるCI検証とは分けて、以下を手元のMacで確認してください。

## 準備

1. Appleメニューの「このMacについて」でCPUを確認します。「チップ」がApple M1以降なら`macos-arm64`、「プロセッサ」がIntelなら`macos-x86_64`を、[v0.4.1の配布ページ](https://github.com/zeusu-sato/codex-usage-tray/releases/tag/v0.4.1)からダウンロードします。
2. ZIPを展開し、**Codex Usage Tray.appを「アプリケーション」フォルダーへ移動**して開きます。Pythonの追加導入は不要です。未公証のため起動が止められた場合は、[既存の導入説明](README.md#日本語での導入)にある個別許可の手順を使います。
3. 確認するCodex／Claude Codeの公式CLIまたはVS Code拡張を普段どおり開き、ログイン済みであることを確認します。新しい会話やプロンプトの送信は不要です。複数のクライアントが見つかった場合は、ミニアプリの「クライアントを選ぶ…」で使っているものを選びます。

## 通常確認 — AIの起動は不要

AI見直しの確認が表示されたら「いいえ (No)」を選びます。片方のサービスだけを使っている場合、未導入・未ログイン側の残量は確認対象外で構いません。

| 確認 | 操作と期待する状態 |
| --- | --- |
| ☐ 2つのアイコン | 画面上部のメニューバーにCodexとClaudeの2個が表示される。公式拡張の画像が見つからなければ、数字や`?`だけでも正常。 |
| ☐ 数字と詳細 | 各アイコンをクリックすると、共通画面の対応するサービスが開く。「更新」後、取得できた側の残量が数字で表示され、詳細の残量・次のリセット時刻と整合する。履歴が少ない間は予測が未確定でも正常。リセット時刻の表示は日本時間（JST）。 |
| ☐ Claudeの対応範囲 | **2.1.263以降の安定版**で取得を試し、上限の版は固定しない。更新後も互換性のある応答なら数字が出る。未導入・未ログイン・非互換などでは`?`と説明を確認し、旧版を無理に導入しない。対象は全体の5時間・週間枠のみ。263・266の静的確認は、将来版やMac実アカウントでの動作保証ではない。 |
| ☐ 追加対策のトグル | 未提案ならOFFでONにできないのが正常。更新で旧対策が停止しても、残量取得は独立して続く。有効な提案が既にあり、利用を望む場合だけON/OFFし、別のサービスの状態が変わらないことを確認する。AIレビューは確認のために必須ではない。 |
| ☐ 閉じても常駐 | 共通画面の左上の赤い閉じるボタンを押しても、2個のアイコンが残る。アイコンから再び詳細を開ける。 |
| ☐ 終了と再起動 | 画面内、またはアイコンの右クリックメニューから「終了」を選ぶと2個とも消える。「アプリケーション」から再起動すると戻る。 |
| ☐ ログイン時起動（任意） | 希望する場合だけ「ログイン時に起動」をONにし、求められたらシステム設定で許可する。作業を保存してログアウト／ログインし、2個のアイコンが戻るか確認する。不要ならOFFに戻す。 |

## AIレビュー（別の任意確認・Codex Usageを消費）

通常確認を終えるために実行する必要はありません。実行を希望し、レビュー可能な状態の場合だけ「AIで見直す…」から説明を読み、**「はい (Yes)」**を選びます。Terminalが開き、Codexで対話形式のレビューが始まることを確認します。**Claudeの対策レビューもCodexのUsageを消費します。** 最高の利用可能モデルと対応する最大の推論設定を使い、自動判定できない場合はTerminalでモデル選択を行います。終了後は「結果を開く」で内容を確認し、対策のONは内容を読んでから判断してください。

確認結果は「MacのCPU／macOSの版／アプリの版／確認した項目と表示されたエラー」だけで報告できます。スクリーンショットやログの添付は不要です。公開する場合も、アカウント名・メール・認証情報・会話内容・個人の指示や未編集のレビュー結果を含めないでください。
